# 版本变更记录文档

> **宗旨**：用最小体积精准记录「改了什么」

> 不写推导过程、不写构建输出、不重复通用约定 

> **项目根目录**：`../`（即当前文件所在目录的父目录），若需要参考其它项目只能以 `只读模式`

> **Github**：用户名 `w2018`，API密钥见系统环境变量名`GITHUB_API_KEY`或者SSH连接

> **开源**：仓库 `https://github.com/w2018/adb-process-killer`

> **约束**：项目根目录新建 `tmp/` 目录，将临时 `.md文档、测试脚本、日志、配置` 等文件，按分类存放子目录，`tmp/`禁止入git库

> **文档**：除 `版本变更记录.md` 外的 `doc/*.md` 禁止入git库

> **版本号**：逻辑为 `逢九进一`，例如 `v0.1.9` 升 `v0.2.0`

> **其它**：架构、版本号、扩展清单与排错速查见文末 **附录** `接手/继续开发前先读`

## 🔴 更新本文档时必须遵守的结构约束（强制）

1. **倒序**：新条目**插到版本区顶部**（最新在最前），**禁止**追加到末尾；
2. **标题**：`## vX.Y.Z`
3. **分类标签**：每条变更必须以 `[新增]` `[优化]` `[修复]` `[破坏性变更]` 之一开头；
   `[说明]` 仅限**版本号 / 兼容性提示**等元信息，且每个条目最多 1 条；
4. **一条一要点**：每条 **≤ 3 行**，只写「问题 → 结论/做法」，**不写**推导过程与验证输出；
5. **禁止冗余**（违反即视为未完成）：
   - 不写构建/检查结果（例如：`vue-tsc` / `lint` / `cargo check` 通过等）；
   - 不写「沙箱无显示器 / 待真机确认」（见下方通用约定）；
   - 不写「未推送 / 未打标签 / 未触发 CI」（只在发布条目里写一次）；
   - 不重复他条已写过的内容 —— 写「详见 vX.Y.Z」即可；
   - 不贴命令输出、日志片段、实测 JSON、测试过程和结果；
6. **版本号**写在正文首行：`版本：文件包名_版本号.后缀` 

## 通用约定（各条目不再重复）

- 🔴 **GUI 交互**：不得声称已验证交互，**必须由用户真机确认** 
- 🔴 **发布纪律1**：默认只本地提交；`git push` / 打标签 / 触发 CI **需用户逐次明确许可**，无CI必须打包发布源码到` Releases` 
- 🔴 **发布纪律2**：首次 `git push` 前，必须主动进行 `脱敏` ，把 `要推送的文件` 以列表形式告知用户，并提醒用户 `清理本地提交的git历史`，确认后才可执行push操作
- 🔴 **改动时**：前端 / 后端 / 侧车任一处改动都**必须重新出包**才生效，版本号严格按要求执行

## v0.1.5

**版本**：com.w2018.procmanager_0.1.5.apk
**主题**： `新增规则与精度优化`

- [新增] **缓存/空进程闲置清理**：清理 oom 缓存档且后台闲置超时的进程，温和省电、误杀低。
- [新增] **内存压力触发清理**：系统可用内存低于阈值时，按占用从高到低回收较重的后台应用。

- [新增] **自启动治理**：设置内新增开机自启应用清单，可按内存排序一键冻结/恢复。
- [优化] **内存精度**：进程内存改用 PSS（dumpsys meminfo）统计，较 RSS 更接近真实占用。
- [优化] **CPU 精度**：进程 CPU 改为 top 3 帧均值采样，降低瞬时抖动导致的误判。
- [优化] **规则开关拆分**：「内存/CPU 超限清理」拆分为内存超限、CPU 超限两个独立开关。
- [说明] 版本 0.1.5，versionCode 6。
